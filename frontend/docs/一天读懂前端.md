# 一天读懂 OmniSupport 前端：学习路线与框架

这份手册对应现有 `Vue 3 + TypeScript + Vite` 客户工作台。按业务调用顺序阅读，遇到语法再补相应知识。

建议净学习时间约 6–7 小时，每 45–60 分钟休息一次。采用连续讲解方式推进，不要求逐题作答；练习保留为可选自查。

## 今天怎样算学会

- 能指出页面入口、界面组件、业务状态、接口请求、工具函数各在哪里。
- 能跟踪登录、切换会话、发送消息、图片提问的完整调用过程。
- 能解释代码中的关键 Vue 与 TypeScript 语法。
- 能独立完成一次小修改，解释为什么改这个文件，并用浏览器和类型检查验证。

## 一、项目的整体框架

### 工具与运行环境

- HTML：浏览器加载的页面结构。
- CSS：颜色、布局、间距、动画与响应式样式。
- JavaScript：浏览器中的交互与执行逻辑。
- TypeScript：在 JavaScript 基础上增加开发时类型检查；类型标注在转换后会被移除。
- Vue：根据状态更新界面，并组织组件。
- Vite：运行开发服务器、处理 `.vue` 与 TypeScript 源码、构建部署文件。
- Node.js / npm：运行开发工具、管理依赖和脚本。
- Python 后端：验证身份、查询数据库、调用模型和业务工具、保存结果。

过去在 Apifox 中完成的请求，现在由前端的 `fetch` 发送；响应由 Vue 展示为页面。

### 启动顺序

```text
浏览器访问 5173
  → Vite 提供 index.html
  → HTML 引用 src/main.ts
  → main.ts 导入样式与 App.vue
  → createApp(App).mount('#app')
  → App.vue 根据登录状态决定显示哪个组件
```

### 组件关系

```text
App.vue
├── LoginForm.vue                 无 Token 时显示
├── 身份验证/重试区域              有 Token、没有客户资料时显示
└── SupportWorkspace.vue          Token 与客户资料均存在时显示
    ├── BrandMark.vue
    ├── ConversationList.vue
    ├── MessageHistory.vue
    │   ├── BrandMark.vue
    │   └── MarkdownText.vue
    └── MessageComposer.vue
```

### 职责分层

| 层       | 负责什么                               | 项目例子              |
| -------- | -------------------------------------- | --------------------- |
| 组件     | 收集输入、展示数据、发出用户操作事件   | `MessageComposer.vue` |
| 业务状态 | 决定何时加载、发送、清空和更新状态     | `useChat.ts`          |
| 业务接口 | 知道接口路径、请求参数、响应结构       | `api/chat.ts`         |
| 公共请求 | 发 HTTP 请求、附加 Token、统一错误处理 | `api/http.ts`         |
| 工具     | 完成独立的数据处理                     | `utils/format.ts`     |

当前项目没有引入 Vue Router 或 Pinia。页面选择由 `App.vue` 的条件渲染完成，状态由组合式函数管理。这是当前规模下的实现选择，不是所有 Vue 项目必须采用的唯一结构。

## 二、关键语法清单

| 写法                            | 属于哪一层        | 需要理解的内容                     |
| ------------------------------- | ----------------- | ---------------------------------- |
| `const` / `let`                 | JavaScript        | 常量绑定、可重新赋值的变量         |
| `import` / `export`             | JavaScript 模块   | 默认导出、命名导出、文件路径       |
| `const { token } = useAuth()`   | JavaScript        | 从返回对象中取出属性，即对象解构   |
| `(...) => ...`                  | JavaScript        | 箭头函数                           |
| `async` / `await` / `Promise`   | JavaScript 与类型 | 异步结果、等待、错误传播           |
| `try` / `catch` / `finally`     | JavaScript        | 成功、失败和最后的状态恢复         |
| `interface` / `type`            | TypeScript        | 描述数据形状，不会自动验证网络数据 |
| `string \| null`                | TypeScript        | 联合类型，数据可能为空             |
| `unknown` 与类型判断            | TypeScript        | 使用未知数据前先检查               |
| `ref` / `.value`                | Vue               | 响应式状态与模板自动解包           |
| `reactive`                      | Vue               | 响应式对象，用于逐步追加回复内容   |
| `computed`                      | Vue               | 从现有状态推导数据                 |
| `watch`                         | Vue               | 状态改变后的副作用与清理           |
| `v-model`                       | Vue 模板          | 输入与状态之间的绑定               |
| `v-if` / `v-else`               | Vue 模板          | 按状态决定创建哪个界面分支         |
| `v-for` / `:key`                | Vue 模板          | 渲染数组，标识每个项目             |
| `:token="token"`                | Vue 模板          | 动态属性绑定                       |
| `@send="send"`                  | Vue 模板          | 监听事件并调用函数                 |
| `defineProps` / `defineEmits`   | Vue 编译宏        | 组件接收的数据与发出的通知         |
| `onMounted` / `onBeforeUnmount` | Vue               | 组件挂载后的操作与卸载前的清理     |

学习时要先辨认代码属于 JavaScript、TypeScript、Vue 还是浏览器 API。例如 `sessionStorage` 和 `AbortController` 是浏览器提供的能力，不是 Vue 自带的状态管理函数。

## 三、四条必须能讲清的调用路径

### 登录

```text
LoginForm.handleSubmit()
  → api/auth.login()
  → http.jsonRequest() → http.apiFetch() → fetch()
  → 返回 Token
  → emit('logged-in', token)
  → App 接收事件，调用 useAuth.acceptLogin()
  → 存储 Token，调用 restore()
  → api/customer.getCurrentCustomer()
  → 得到客户资料，App 显示工作台
```

### 选择会话

```text
ConversationList 点击条目
  → emit('select', id)
  → SupportWorkspace.select(id)
  → useChat.selectConversation(id)
  → 清理上个会话的显示状态
  → loadHistory() → api/conversation.getConversationMessages()
  → messages 更新 → MessageHistory 更新界面
```

### 发送消息

```text
MessageComposer.submit()
  → emit('send', 输入数据)
  → useChat.send()
  → 创建本地待完成的用户与客服消息
  → 按是否有图片、是否开启流式选择接口
  → 逐步显示回复
  → 成功后确认完成状态、保存会话编号、清空草稿、刷新列表
```

### 图片提问

```text
用户选择图片
  → 前端检查类型和大小
  → Object URL 提供本地预览
  → 发送时使用 FormData
  → 后端再次验证文件并识别图片
  → 返回客服回复与会话编号
  → 历史中保存问题、观察文字与回复；原文件未持久化
```

## 四、可选自查与操作

每项练习先预测结果，再修改，再观察，最后解释。一次只改一个地方；涉及业务聊天时，先用普通问候测试，避免把真实业务操作当成语法练习。

1. 修改浏览器标签页标题，观察与页面内标题的区别。
2. 看着代码，说出 App 的三个条件分支分别需要什么状态。
3. 独立定义一个包含 `message` 与 `conversation_id` 的 TypeScript 接口。
4. 找到发送按钮的禁用条件，解释空输入、发送中和历史读取失败分别如何影响它。
5. 跟踪 `logged-in` 和 `send` 两个事件，指出谁发出、谁接收、携带什么数据。
6. 在 Network 中找到登录 POST、资料 GET 和会话 GET，说明请求参数位于哪里。不要分享密码、Token 或完整请求头截图。
7. 新建对话发送普通问候，再继续一句，解释两次请求中 `conversation_id` 的变化。
8. 比较普通 JSON 响应与 SSE 的 `token`、`done`，解释 HTTP 200 为什么不足以证明流式业务完成。
9. 找到取消读取请求的位置，说明取消浏览器等待为什么不等于撤销后端已执行的写入。
10. 修改一个颜色变量，观察哪些组件受影响，再恢复。
11. 选择图片后检查 `FormData`，解释为什么代码没有手写 multipart 的 Content-Type。
12. 独立完成一个小功能：例如调整欢迎语或增加一个只填入草稿、不自动发送的快捷问题。

## 五、排查问题的顺序

1. 页面没有启动：看终端与 Vite 启动状态。
2. 页面报类型错误：运行 `npm run typecheck`，先读第一条错误。
3. 点击没有反应：追踪模板事件、处理函数、组件发出的事件。
4. 请求失败：看 Network 的请求地址、方法、状态码与响应；`Failed to fetch` 不代表密码错误。
5. 数据返回但界面不变：检查是否写入正确的响应式状态、是否修改了响应式对象，以及条件分支。
6. 切换后显示错数据：检查请求取消与当前请求/会话的比较。
7. 样式错位：用浏览器元素检查定位 class，查看 CSS、可用高度和响应式断点。
