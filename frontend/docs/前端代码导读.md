# 前端代码导读

## 先看整体分工

```text
src/
├── App.vue                       决定显示登录页、身份加载页还是工作台
├── api/
│   ├── config.ts                 统一后端地址
│   ├── http.ts                   公共请求、错误类型、响应结构检查
│   ├── auth.ts                   登录与注册接口
│   ├── customer.ts               当前客户资料接口
│   ├── conversation.ts           会话与历史消息接口
│   ├── chat.ts                   普通聊天与 SSE 消息流
│   └── image.ts                  图片校验与 multipart 问答
├── composables/
│   ├── useAuth.ts                登录凭证、客户资料、恢复和退出
│   └── useChat.ts                会话选择、历史分页、发送与保存状态
├── components/
│   ├── LoginForm.vue             登录、注册表单
│   ├── SupportWorkspace.vue      工作台布局、移动抽屉、会话信息
│   ├── ConversationList.vue      展示列表、搜索、通知选择事件
│   ├── MessageHistory.vue        消息显示、滚动、复制、图片观察详情
│   ├── MessageComposer.vue       输入框、图片预览、流式开关
│   ├── MarkdownText.vue          清理并显示 Markdown
│   └── BrandMark.vue             可复用品牌标识
├── utils/format.ts               时间、标题与图片历史文本处理
└── style.css                     设计变量、页面样式、响应式断点
```

`composables` 是 Vue 中复用状态逻辑的常见目录。`useAuth()` 和 `useChat()` 是普通函数，内部组合 `ref`、`computed`、`watch` 等 Vue API，最后把页面需要的状态和操作返回。

## 1. 登录是怎样连接起来的

1. `LoginForm.vue` 收集邮箱、密码，调用 `api/auth.ts` 的 `login()`。
2. 成功后 `emit('logged-in', token)` 通知父组件。
3. `App.vue` 通过 `@logged-in="acceptLogin"` 接收事件。
4. `useAuth.ts` 保存 Token，再调用 `/customers/me` 验证身份并获取客户资料。
5. 只有 Token 和客户资料都存在时，才显示 `SupportWorkspace`。

Token 保存在当前标签页的 `sessionStorage`，不保存密码。它能让刷新后继续使用，但不是可信的身份来源：后端会重新验证每一个受保护请求。

## 2. props、emit、ref 各负责什么

- `props`：父组件把数据交给子组件。例如 `:items="conversations"`。
- `emit`：子组件通知父组件发生了什么。例如点击会话后发出 `select` 事件。
- `ref`：保存会变化、需要更新页面的数据。脚本中使用 `.value`，模板中自动解包。
- `computed`：根据其他状态计算结果，例如当前会话标题、发送按钮是否可用。
- `watch`：状态变化后执行操作，例如 Token 变化时清理旧会话。

## 3. 发送一条消息的过程

```text
MessageComposer 校验草稿
  → emit('send', { text, file, stream })
  → useChat.send()
  → 调用普通聊天 / SSE / 图片问答接口
  → 更新当前消息的状态
  → 成功后保存 conversation_id，清空输入，刷新会话列表
```

发送中的客户消息和客服消息先用临时 ID 显示。普通成功响应或 SSE 的 `done` 表示后端已完成消息保存，才会标记完成并增加已保存消息数。重新打开会话会读取数据库中的正式记录。

失败时保留草稿，未确认的消息会显示提示，不会自动重发。对于可能触发退款申请等业务工具的聊天，自动重发可能导致额外业务操作，因此读取重试与业务发送必须分开。

## 4. 为什么 SSE 要单独解析

`api/chat.ts` 使用 `fetch()` 发送带 Token 的 POST 请求，再从 `response.body` 分片读取。网络分片与事件边界不同，可能把中文 UTF-8 字节或 `\r\n` 切开，因此需要：

1. 用带流模式的 `TextDecoder` 解码字节。
2. 保留尚未完整的事件内容。
3. 遇到空行后解析完整的 `event` 与 `data`。
4. `token` 追加文字，`error` 报告失败，`done` 确认业务完成。

连接关闭本身不代表成功，不能把断流误显示为“已保存”。

## 5. 如何防止切换会话后出现旧消息

`useChat` 为列表和历史读取分别维护 `AbortController`。新读取开始时取消旧读取，接收结果前再比较当前请求与会话编号。退出或组件卸载时也会清理读取请求和图片预览 URL。

发送期间禁用新建、切换与退出，避免用户在业务请求未完成时混淆当前会话。组件销毁不能保证服务器端的写操作被撤销。

## 6. 图片处理

`MessageComposer` 使用 `URL.createObjectURL()` 做本地预览，切换图片、清空或卸载时撤销 URL。真正发送通过 `FormData`，不能手工设置带 boundary 的 Content-Type。

后端负责真实文件签名、完整性、像素限制和权限验证。前端的 MIME 与大小检查只是提供更早的用户提示。

历史图片观察文字仍然是 AI 生成内容，不能当成系统指令或商品身份凭证。`splitImageMessage()` 将客户原问题和观察文本拆开展示，不修改数据库记录。

## 7. Markdown 为什么要清理

`marked` 负责把 Markdown 转换成 HTML，不负责消除危险内容。`MarkdownText` 使用 DOMPurify 白名单清理结果，去掉脚本、事件属性、危险 URL 和外部图片等内容，再交给 `v-html`。不要在其他组件里直接把模型回复传给 `v-html`。

## 8. 以后应该在哪里改

| 需求                           | 优先修改的位置                                         |
| ------------------------------ | ------------------------------------------------------ |
| 更换服务地址                   | `.env.local`、`api/config.ts`                          |
| 修改品牌颜色、间距和响应式布局 | `style.css` 的设计变量与对应分区                       |
| 增加一个业务接口               | `api/` 对应业务文件                                    |
| 调整消息发送流程               | `composables/useChat.ts`                               |
| 修改聊天气泡、表格或图片显示   | `MessageHistory.vue`、`MarkdownText.vue`               |
| 修改输入框、快捷键或图片附件   | `MessageComposer.vue`                                  |
| 添加工作人员管理页面           | 新建对应页面、接口和权限流程，不能复用客户身份绕过权限 |

建议下一次先读懂 `MessageComposer → useChat.send → api/chat` 这一条路径，再学习历史分页和登录恢复。每次修改后执行 `npm run typecheck`，涉及页面或打包时再执行 `npm run build`。
